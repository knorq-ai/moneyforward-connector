# MF 会計 API / UI 運用メモ

クラウド会計を API と UI のハイブリッドで運用して分かった、仕様書に書かれていない挙動。
金額・氏名はすべて例示値に置き換えてある。

## 1. API 投入仕訳と銀行連携は二重計上になる

最大の落とし穴。MF は API で POST した仕訳と「自動で仕訳 → 連携サービスから入力」の銀行 feed 取引を**自動でリンクしない**。

- 同じ取引を API で POST してから銀行 feed 側を承認すると、両方が独立した仕訳として残り、台帳が二重になる
- 二重計上を避けるには、**銀行口座の入出金が絡む仕訳は API で POST しない** ことを徹底する
- 既に重複させてしまったときの復旧は、API 側を `DELETE /journals/{id}` で削除し、UI 側で承認するのが最もクリーン

### API で POST してよいパターン

- 売上計上 (請求書発行 → 売掛金/売上高)
- 業務委託費・給与の発生計上 (期末 / 支給日基準)
- 売掛金回収のうち**役員預け金経由など銀行 feed に出ないもの**
- 借方/貸方とも法人銀行口座を含まない振替

### UI に任せるべきパターン

- 法人銀行口座の入出金が一方の借/貸に出てくるすべての取引（資本金払込、給与振込、社会保険料納付、手数料、立替返済、利息など）

呼び出し側で「借方・貸方に銀行口座の sub-account が含まれていないか」を POST 前にチェックするとさらに安全である。

## 2. MF の自動仕訳サジェストは賢くない

UI の「自動で仕訳」は単純な摘要文字列マッチでデフォルト勘定科目を出す。摘要が同じ（例: `振込 <代表者名カナ>`）2 件の入金を、金額が桁違いでも両方とも「売上高 / 課売 10%」と提案してくる。実際には一方が立替金の返済、他方が資本金の払込、という具合に中身は別物である。

- 自動承認に頼らず、各エントリの内容で勘定科目・税区分を上書きする運用が必須
- 「自動仕訳ルール」機能で摘要 → 勘定科目のマッピングを登録すれば未来の同種取引は自動化できるが、初回は手動

## 3. UI 詳細仕訳の各 branch は API と同じく借貸一致が必須

複数 leg の仕訳を UI 「詳細」で組むとき、+ ボタンで追加した行は**独立した借方/貸方ペア**として扱われる。
社会保険料の引き落とし 100,000 を「法定福利費 60,000 + 預り金 40,000」に分割するなら、

- 1 行目: 借 法定福利費 60,000 / 貸 普通預金 60,000
- 2 行目: 借 預り金 40,000 / 貸 普通預金 40,000

の 2 branch として組む。API の `branches[]` と同じ構造で、各 branch の借貸が一致しないと登録ボタンが disabled になる（「不足額 X 円」と赤字表示）。

## 4. INVOICE_KIND_UNQUALIFIED_80 は `tax_value` が黙って再計算される

API で `tax_value` を渡しても、`invoice_kind=INVOICE_KIND_UNQUALIFIED_80` の場合は MF 側で 80% に縮小される。たとえば送信値 1,375 → 実体 1,100。

- 仮払消費税の控除可能額（80% 経過措置）が反映された結果なので意味的には正しい
- 呼び出し側は **`tax_value` をヒントとして渡し、レスポンスの値を信頼する**。事前に 80% 計算する必要はない
- ログや idempotency ハッシュには **送信時の `tax_value` ではなく `value (税込)` と `invoice_kind` を使う** べき

## 5. 税区分は勘定科目変更で自動追随する

UI で 勘定科目を変えると 税区分が自動でその勘定の既定値に切り替わる（例: 売上高→資本金 にすると 課売 10% → 対象外）。API でも `tax_id` を省略すれば勘定の既定値が当たる。

- UI で勘定変更後に税区分を見直すのは不要なことが多い
- ただし「ChatGPT サブスク = 不課税（海外電子サービス）」のように勘定既定と乖離するケースは手動で 税区分 を上書きする必要がある（ソフトウェア利用料の既定は 課仕 10%）

## 6. 預り金 sub-account は 健保/厚年/子育て を分けない

MF 標準では `預り金` の補助科目は `社会保険料 / 雇用保険 / 所得税 / 住民税` の 4 つ。健康保険・厚生年金・子ども子育て支援金は**全部「社会保険料」サブにまとめる**運用になる。

- 仕訳の摘要に「健保 xx,xxx + 厚年 xx,xxx + 子ども子育て xxx」のような内訳を残す
- 内訳まで台帳に出したいなら、自前で sub-account を追加するか、会計ソフトの外に内訳メモを持つ

## 7. UI コントロールの実用 tips（ブラウザ自動化で操作する場合）

- 勘定科目ドロップダウンは type-to-search が効く。クリック後に和文を打つと候補が絞り込まれる
- 「対象外」「対象外売」「対象外仕」は別 ID。仕入側に「対象外仕」がデフォルトで当たる勘定が一部ある（業務上の影響は同じ）
- 詳細パネル左の `+` は新規 branch 追加、`−` は branch 削除
- 連携サービスから入力ページは登録すると行が消えるので、座標ベースで連続クリックする場合は順序に注意
- 「自動仕訳ルールとして保存」チェックを外さないと、その仕訳の勘定マッピングがルール化されて次回以降自動適用される（意図しない学習を防ぎたいならオフ）
